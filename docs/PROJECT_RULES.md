# Ver8.0での変更点

Sprint18（総合評価エンジン＆手入力最小化）の開始に伴う改訂。
旧Verにあった「将来のアイディア」から実用性の高いものをロードマップに再編した。

・**外部依存の禁止**: Yahoo! Financeの新規機能への利用・依存拡大を禁止。今後は既存の取得済みデータの活用や、官公庁の一次データ（EDINET/SEC EDGAR）の自動取得へシフトする。
・**UXの改善**: ユーザーの手入力を極限まで減らす（DCFの自動プリセット、フォームのUI改善など）。
・**サマリータブの強化**: サマリータブの最上部に【バフェット総合評価（Buffett Overall Grade & 最終結論）】を新設し、一目で投資判断ができるようにする。
・**ロードマップ更新**: Owner Earnings、ROIC、有価証券報告書解析、AIチャットなど実用性の高い機能を今後のSprintに組み込んだ。

# プロジェクト理念

このアプリは **「ウォーレン・バフェットなら投資するか？」** をAIで分析することを目的とした投資分析アプリである。
単なる情報提示ではなく、ユーザーの手入力を最小限に抑え、一目で「バフェットの最終結論」を導き出せるUI/UXを提供する。

---

# 最重要ルール

1. **既存コードを壊さない**: 新機能追加は追加または拡張で対応する。既存機能を書き換えない。
2. **app.py全体を確認する**: 部分コードだけ見て修正しない。整合性を確認する。
3. **コピペで動くコードを書く**: 途中だけのコードは禁止。そのまま貼れば動く完成版を書く。
4. **リファクタリング禁止**: ユーザーが希望しない限り構成を変更しない。
5. **初心者向けに説明**: 何をするか、どこへ貼るか、どう確認するかを明確にする。
6. **新規モジュールの配置場所**: 新規作成するファイルは、必ず既存モジュール（`services/` 配下）と同じフォルダに配置する。
7. **Yahoo! Finance依存拡大の禁止**: 取得元としての新規追加は行わない。

---

# Streamlitルール・UI改善方針

・**入力フォームの削減**: 登録や設定項目は `st.popover` などを活用し、メイン画面の視覚的ノイズを減らす。
・**長文の格納**: 情報量の多いテキスト（詳細分析など）は `st.expander` に格納し、スクロール量を減らす。
・**Session State**: 状態保持は `st.session_state` を使用し、グローバル変数は禁止。

# AIルール

・使用するAIは **Gemini のみ**（OpenAIへ戻さない）。無料枠内で実現できる範囲とする。
・各AI関数はGemini APIキー未設定・エラー時にルールベース関数へ自動フォールバックする設計を維持する。

## Version2 Architecture Rules

- app.py は画面制御のみを担当する。
- analysis フォルダには分析・計算ロジックのみを配置する。
- ui フォルダには Streamlit の表示ロジックのみを配置する。
- AI（Gemini）の呼び出しは analysis_bundle 作成時のみ行う。
- UI コンポーネントから直接 AI を呼び出してはならない。
- 新機能追加時は app.py の変更を最小限にする。
- 新しい分析機能は analysis 配下へ追加し、UI は ui 配下で表示する。
